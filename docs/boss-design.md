# boss skill 方案书 v0.1

日期：2026-09-07。状态：已实现 SKILL.md、协议、成本规则与四个平台适配说明；结构校验及独立行为场景审查已完成。未进行四平台端到端实测，自动恢复依赖宿主能力。本文记录设计与验证边界，实际运行入口为 [SKILL.md](../skills/boss/SKILL.md)。

## 1. 产品目标与范围

`boss` 让当前 session 的模型保留需求理解、关键决策与验收职责，把边界清晰的执行工作交给用户指定或自动选择的低成本子代理。核心收益是让高能力模型的上下文和推理投入集中在高价值判断上。

第一版优先落地 Codex；Claude Code、OpenCode、pi 提供适配指导，再分阶段验证。速度与成本采用可调整的“均衡节省”默认策略。

当前交付是可安装的指令型 skill，包含运行入口、任务协议、成本规则和平台适配说明，不包含独立调度服务或自动恢复扩展。运行时不修改全局模型配置；平台不能原生完成的事情，明确归入可选适配层。

成功标准有先后顺序：遵守模型与权限硬约束 → 满足用户验收标准 → 减少 Boss 执行负担和额度消耗 → 控制延迟。不能通过降低正确性或隐瞒失败来获得表面节省。

## 2. 不可破坏的规则

1. **Boss 就是当前 session 的模型。** 不另起一个强模型充当 Boss，不切换主会话模型，不把默认配置误认为当前有效模型。
2. **显式 Worker 模型是会话级硬约束。** 开头指定一次即在整个 session 持续生效，后续无需重复调用 `$boss` 或重复指定模型；用户可再次切换。新委派及后续跟进必须遵守当前选择，不能静默回退到继承模型、其他模型或其他 provider。切换前已经运行的任务按第 7 节的切换规则处理。
3. **Boss 自己理解整体需求。** Boss 提取意图、约束、验收标准和依赖关系。Worker 可定位事实、提出局部建议、实现叶子任务，但不接管整体需求解释和架构裁决。
4. **默认最小上下文。** 不复制完整对话，不传整份方案书，不让 Worker 自己追溯聊天历史。必需的项目规则、授权边界和任务证据不能为了压缩被省略。
5. **委派必须有收益。** 不因调用 `$boss` 就机械创建 Worker；简单任务可由 Boss 直接完成，并说明未委派的原因。
6. **结果必须可核查。** Worker 的“完成”只是报告，不等于 Boss 验收通过。关键结论须附文件位置、命令结果、测试证据或来源。
7. **能力与计费都要诚实。** 不把“有子代理工具”当成“可指定模型”，不把“少用 Boss token”当成“已证明省 Plus 额度”。

显式模型约束限制的是子代理用什么模型，不禁止 Boss 完成自己的判断、整合和必要的短小修复。但指定模型不可用时，不能悄悄把整份执行工作交回 Boss 并声称完成了指定委派；应暂停受影响的委派并说明原因。若用户同时要求必须委派，则不能用直接执行满足该要求。

## 3. 用户交互

建议支持自然语言，不要求用户记一套参数语法：

```text
$boss，使用 gpt-5.6-luna 作为子代理模型，帮我修复这个问题。
$boss，自动选择低成本子代理，优先节省额度。
继续处理下一个问题。                     # 自动沿用当前 Worker
把 Worker 切换成 gpt-5.6-terra。           # 更新本 session 的后续选择
后续 Worker 恢复自动选择低成本模型。       # 显式解除固定模型锁定
```

首次执行前简短展示实际状态；以下是模型已由运行时确认时的示例，不是对本次会话身份的检测结果：

```yaml
Boss: gpt-6-astra
Worker: gpt-5.6-luna
Mode: native-dynamic
```

身份不可读时显示 `Boss: current-session (model-id unavailable)`，仍由当前会话负责总控。Worker 尚未启动时，展示的是已解析的选择，不能写成已经执行。

需要时追加 `Model assurance: runtime-reported | configuration-verified | unverified`。平台返回的身份与 Worker 自己在文字里声称的身份不是一回事；后者不能作为校验依据。

正常过程只报告关键决定、阻塞与结果；不向用户倾倒完整任务包、调度日志或推理过程。首次设置与切换时显示模型状态，普通后续轮次无需重复展示。模型选择持续到用户修改或本 session 结束；运行时能力变化只触发重新校验，不能自动解除锁定或替换模型。

## 4. 能力探测与运行模式

先读取当前平台暴露的工具定义和可信会话元数据，再按需读取一个平台适配文档。避免为每次调用扫描全部配置、全部技能或全部平台文档。

| 探测项 | 目的 |
| --- | --- |
| 当前有效模型及证据来源 | 尽可能显示 Boss 真名；未知则明确标注 |
| 可用模型、provider、账号路径 | 解析 Worker，避免选择无权限的模型或改变计费渠道 |
| 子代理模型参数与配置优先级 | 确保最终生效值符合用户选择 |
| 无历史启动能力 | 落实最小任务包，区分业务上下文与平台必需上下文 |
| 子代理生命周期控制 | 确认等待、跟进、取消与完成状态如何获取 |
| 工作区及权限隔离 | 防止并发覆盖，保证 Worker 不扩大授权 |
| 用量与模型回执 | 确定哪些信息能测量，哪些只能标注未知 |

模式由实际能力决定，不能按平台名称直接猜测：

| Mode | 使用条件 | 行为 |
| --- | --- | --- |
| `native-dynamic` | 原生调用可指定模型，并可控制历史传递 | 直接用原生子代理，首选 |
| `native-configured` | 原生子代理通过已生效角色配置选择模型 | 选中严格匹配的角色，检查覆盖关系 |
| `adapter-backed` | 已安装且授权的扩展或桥接提供所需能力 | 保持主会话为 Boss，扩展只执行 Worker |
| `direct` | 任务太小或不适合委派，且用户未要求必须委派 | Boss 直接做，透明说明 |
| `blocked` | 指定模型不可用、配置冲突或无法满足必要约束 | 不启动不合规 Worker，报告具体缺口 |

纯 skill 是指令，不能创造工具参数、模型访问权或运行时隔离。只有提示词约束时，承诺的是“按规则选择并检测可见违例”；要强制防止模型回退，需平台或适配器提供校验与拒绝机制。

模型身份允许分级证据：有效运行时元数据最佳；经过验证、无冲突的实际配置次之；只有默认配置或模型自报则不足。若存在可能覆盖指定模型的未知配置，暂停严格委派。后端没有返回真实模型 ID 时，只能报告配置已验证，不能宣称服务端实际模型已核实。

## 5. 平台适配边界

下表是文档与当前工具契约的核查结果，非四平台实测认证。工具签名以目标安装的实际版本为准。

| 平台 | 已核实的基础 | 第一版处理 |
| --- | --- | --- |
| 当前 Codex 会话 | `spawn_agent` 提供 `model`、`reasoning_effort`、`fork_turns`；全历史 fork 不允许模型覆盖 | 显式模型 + `fork_turns: "none"`；本次只验证了契约，未派发探针 |
| 其他 Codex 环境 | 官方支持子代理模型默认值与自定义 agent 配置 | 检查实际工具与配置优先级，不能照搬当前会话签名 |
| Claude Code | 自定义 subagent 可设置 `model`、工具和运行限制 | 优先匹配已生效的角色配置；检查模型覆盖与上下文模式 |
| OpenCode | agent 配置支持 `mode: subagent` 和 `provider/model-id` | 验证对应角色的模型与权限，再委派；不假设调用级模型覆盖 |
| pi | 官方仓库提供独立进程、隔离上下文的 subagent 扩展示例 | 有兼容扩展才启用适配；示例存在不等于用户已安装 |

Codex 的自定义 agent 文件可以覆盖显式 spawn 模型，因此“调用里写了 Luna”并不在所有安装中足够。必须检查实际选择的角色配置，不能选固定强模型角色后假定调用参数更优先。[Codex 子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)

Claude Code 的角色模型与配置作用域见[官方子代理文档](https://code.claude.com/docs/en/sub-agents)。OpenCode 未指定子代理模型时会继承主代理模型，且模型配置使用 provider/model-id，见[官方 Agents 文档](https://opencode.ai/docs/agents/)。pi 的实现基础是[官方 subagent 扩展示例](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/extensions/subagent)。

跨平台适配指“统一行为协议可映射到平台能力”，不代表一个 Markdown 文件能在所有版本零配置运行，也不代表 Plus 订阅在其他平台自动提供同样的模型权限。

### Codex 第一版的最短实现路径

直接复用 Codex 原生 Multi-Agent，skill 仅负责调度规则、会话级 Worker 选择与验收协议。当前会话已选择 Astra 时，Astra + Luna 是适用的示例组合；不为套用示例而修改当前 Boss 模型。

在当前工具契约下，派发形态如下；这是需要补全任务内容的示意，不是已执行的调用：

```text
spawn_agent(
  task_name = <叶子任务名>,
  model = <session 当前锁定的 Worker 完整 ID>,
  reasoning_effort = <受支持且适合任务的强度>,
  fork_turns = "none",
  message = <最小任务包>
)
```

每次派发显式使用当前选择；不依赖遗漏参数后的模型继承。默认不新增 custom-agent role；已有角色会影响生效模型时仍需检查。全局 `[agents]` 默认值可作为用户另行选择的环境便利设置，但不是 boss 的必要安装步骤，也不能代替可切换的 session 状态。

继续使用用户现有的 Codex 登录与计费路径，不为实现调度额外搭建 API 调用层。第一版不写全局 `model`、不将 Boss 固定为 `max`、不把 6 个并发当成目标。官方确认相关子代理默认配置字段存在，但高推理强度会增加时间和 token 消耗。[Codex 子代理配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)

兼容性以目标运行时的工具契约和行为验证为准，记录已测试版本，不将某个最新版本号写成永久保证。首次实现时用一个有实际价值的小任务验证模型选择、无历史启动、结果回收和跟进；若没有模型回执，保留配置验证等级，不声称已验证后端身份。之后仅在版本、配置或选择变化时重新检查相关能力，避免每轮额外探针开销。

## 6. Boss 调度流程

```text
用户 Prompt
  → Boss 提取目标、约束、验收标准
  → 必要的定向事实定位（可委派，只返回事实）
  → Boss 决定方案、叶子任务和依赖
  → 能力与模型校验
  → 最小 delegation packet
  → Worker 搜索 / 读取 / 实现 / 测试 / 批处理
  → 压缩 result + evidence
  → Boss 验收、定向纠偏、整合、最终回答
```

适合委派：按具体问题定位调用链、从限定资料抽取事实、按既定接口实现一个模块、执行指定检查并归纳失败、批量转换同类文件。

保留给 Boss：含糊需求消歧、冲突约束取舍、跨模块设计、改变用户预期的决定、最终是否完成的判断。开放问题不是完全不能委派：先让 Worker 收集有限事实，Boss 据此收敛问题。

委派前做短判断：结果是否易验收？输入是否足够小？执行量是否超过启动与沟通成本？失败是否可局部修复？若给 Worker 解释任务比直接完成更费力，选择直接执行。

对边界已清楚、具有实质执行量的搜索、阅读、实现、测试和批处理，默认优先委派，避免 Boss 先通读全部材料、再把同样工作交给 Worker。Boss 只先读足够确定方向的入口和关键约束；执行后的原始日志留在 Worker，Boss 按证据定向复核。这里的“完整上下文”指用户目标、约束与全局决策，不要求 Boss 预先读取所有文件。

当前平台若要求委派必须与有用的本地工作并行，先确认 Boss 同时能推进验收准备、接口决策或其他独立工作；不为满足流程编造忙碌任务，也不派发后重复 Worker 工作。没有适用的独立工作时遵循平台限制，不能采用“所有小任务一律交给一个 Luna”的固定规则。

官方说明 Astra 经过并行子代理委派训练，并建议通过提示明确何时委派；这支持在 skill 中写清优先委派条件，但不证明任何拆分都更省钱。[Astra 委派指南](https://developers.openai.com/api/docs/guides/latest-model#subagent-delegation)

任务粒度以“一个可验收交付物”为准，不按一次工具调用拆分。共享输入的同类小任务合并；不要创建规划者、规划审查者、实施者、实施审查者组成的固定流水线。

建议默认最多 2 个并发 Worker，受平台更低限额约束；只为独立工作并行。写同一文件的任务串行，或使用真正隔离的工作区并由 Boss 整合。共享测试状态、浏览器会话、数据库也视为冲突资源。等待应使用事件或阻塞等待，避免高频轮询。

## 7. 模型选择策略

### 会话状态与切换

首次启用 boss 后，在当前 session 保留调度规则和 Worker 选择，后续普通消息自动沿用，不要求每轮重新触发 skill。持久化的是模型选择策略，不是同一个 Worker 实例：不同任务仍可启动新的隔离子代理。

建议保留最小状态：`session_id`、`selection_mode: fixed | auto`、`requested_model`、`resolved_model_id`、`provider`（若可得）、`selection_revision` 和校验证据。显式选择进入 fixed；只有用户明确要求恢复自动选择，才进入 auto。auto 保留自动选择策略，可按任务选择合适的低成本候选，不承诺锁定某个模型。

切换规则：

- 用户再次指定 B 后立即更新目标选择并递增版本；所有尚未启动的任务及新的跟进使用 B，启动前仍须验证。若 B 不可用，则暂停这些委派，不自动继续使用 A。
- 默认允许切换前已运行的 A 任务完成，明确提示“后续使用 B，已有 A 任务继续完成”。这些任务的结果保留原模型和版本标记，不因切换本身作废。
- 切换后不再给 A 实例追加工作或纠偏；需要继续时，用最小任务包交给新的 B 实例，不假定平台能原地切换运行中子代理的模型。
- 用户要求“立即全部切换”时，先停止旧任务、核对已产生的改动，再由 B 继续剩余工作；不能重复执行已完成的副作用。
- 用户在一次消息中指定新模型并提出任务时，先应用新选择，再安排任务。切换仅更新 Worker，不改 Boss。

上下文压缩、同一 session 的恢复不得清空选择。优先使用平台会话状态；需要外部状态时按 session ID 隔离保存，只载入最小记录，不能写入全局默认模型配置或把别的会话选择带入新会话。恢复后重新校验可用性，但保留用户锁定。新建或 fork 的独立 session 不自动共享可变状态。

纯 Markdown skill 的持续生效依赖平台保存指令与会话状态；若平台在压缩或重启后无法可靠保留，需要适配层补足，并将该项标为未支持。无法恢复选择时，应说明状态缺失并询问，不能猜测或静默使用默认模型。

### 选择与解析

显式选择优先于自动选择。用户短名如 `luna` 只在可用目录中唯一对应时解析成完整 ID；歧义时询问。保留原始选择和解析结果，不能将相似名字当成同一个模型。模型与 provider 是联合身份，不能为了省钱改用不同提供方。

自动模式的顺序：用户已确认的当前会话偏好 → 当前账号可用且有成本依据的候选 → 满足叶子任务工具、上下文和输出要求的低成本模型。当前 Codex 工具目录列出 `gpt-5.6-luna`，可作为窄任务候选；模型列表与价格不写死为跨平台常量。

官方将 Astra 定位于复杂工作、Luna 定位于清楚且可重复的任务，符合本方案的职责分配；但这不等于 Luna 适合所有实现工作。[官方模型说明](https://learn.chatgpt.com/docs/models)

没有可靠成本排序时显示 `cost ranking unknown`，不声称选到了最便宜模型；可沿用已确认的低成本偏好，否则先澄清必要选择。自动选择也不能自行新增 API 付费渠道。

Worker 推理强度建议从模型默认或受支持的 low/medium 起步，根据任务难度选择；不自动继承 Boss 的高推理设置。用户显式指定 effort 时同样遵守。Boss 不由 skill 强制调高或调低推理强度。

## 8. 最小 delegation packet

以下是协议示例，不是每次必须生成的冗长 YAML。短任务可用等价的简洁文字，字段以足够执行为准。

```yaml
task_id: fix-empty-input
objective: 按已确认规范修复空输入处理
context:
  facts: [调用方允许空字符串]
  decisions: [空字符串返回空结果，公开函数签名不变]
inputs:
  files: [src/parser.ts, tests/parser.test.ts]
scope:
  writable: [src/parser.ts, tests/parser.test.ts]
  forbidden: [修改公开接口, 引入依赖, 重构其他模块]
acceptance:
  - 空输入返回空结果
  - 现有正常输入行为保持一致
verification:
  - 使用项目现有命令运行 parser 相关测试
constraints:
  - 遵守作用于这些文件的项目指令与当前授权
  - 不继续委派；缺失信息或语义冲突时回报 Boss
budget:
  correction_rounds: 1
return:
  - 状态、改动摘要、文件位置、检查命令和结果、未解决事项
```

模型选择由 Boss 在调用/适配层设置，不靠任务包里写“你是 Luna”实现。传递已决定的事实和理由摘要，不要求或转发内部逐步推理。Worker 需要发现适用的本地规则；必要规则若不会被平台加载，就在包中给出具体引用或内容。

长文档提供文件引用和相关段落位置，避免粘贴全文；但不强制极短包导致 Worker 反复追问。初始建议包正文控制在约 1,000 tokens 内，复杂交付允许扩大；只是软目标，不为凑长度丢约束。平台系统提示、工具定义和自动注入规则的 token 仍须计入成本。

## 9. Worker 返回与 Boss 验收

建议返回结构：

```yaml
task_id: fix-empty-input
status: done # 或 partial / blocked / failed
summary: 修复空输入分支并补充行为测试
artifacts:
  - path: src/parser.ts
    note: 空输入处理位置
evidence:
  - command: <实际运行的项目命令>
    exit_code: 0
    result: <实际检查数量与结果>
    log_ref: <仅在需要时保存的日志位置>
open_issues: []
```

不能把“没跑检查”写成“检查通过”。搜索结果应保留来源和必要原文位置，代码结果应保留可定位的改动和检查证据。失败、反例、未验证项不能因摘要长度限制被省略；长日志保留引用，正文只给决定性片段。

Boss 对照验收标准检查结果及关键 diff；证据不足时定向补查，而非全部重做。跨任务集成后运行必要的集成检查。Worker 已有效执行且环境未变化的检查不机械重复。

首次未通过时，Boss 给出具体缺口和一次聚焦纠偏，优先继续同一个任务的 Worker。再次失败则重新判断任务拆分、Boss 接管小范围关键点或询问必要输入；不无限重试。显式 Worker 模型不能随失败升级。自动模式也先分析失败原因，不把基础设施错误当作模型能力不足。

用户取消时停止相关 Worker；用户变更需求时只使受影响任务失效。收到过期结果先核对任务版本和文件状态，再决定能否整合。会话压缩后保留最小状态：模型锁定、未完成任务、验收标准、证据位置及重试次数，防止重复派发。

## 10. 节省额度的衡量方式

用户已确认：**以官方 token 价格作为主要成本衡量口径**。使用各模型官方公布的 token 单价，将实际用量折算为可比较的价格成本，用于自动选择 Worker、判断委派收益和比较运行方案。Plus 账号额度变化只作辅助观察，不作为主要优化指标。

订阅登录场景下，这个指标称为“官方价格折算成本”，不是实际 API 账单，也不等同于 Plus 额度扣减；采用这一口径不意味着改用 API key。[官方价格与用量说明](https://learn.chatgpt.com/docs/pricing)

官方也明确说明子代理会增加模型与工具工作，总 token 可能高于可比的单代理执行。因此本方案追求的是用低成本执行替换部分高成本执行，并控制额外开销；不是“子代理免费”。[官方子代理说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)

每次评估使用与准确模型 ID 对应的官方价格，记录来源 URL、查询日期、币种、计价单位及适用档位。区分普通、缓存、长上下文、批处理或速度档位等适用条件；不能套用当前运行不符合条件的优惠价。一次对照比较固定同一价格快照，避免价格更新干扰结果。不在 skill 中永久写死价格表；按需查询并复用带时间戳的快照。

按官方每百万 tokens 单价计算：

```text
单次调用成本 = (未缓存输入 tokens × 输入单价
              + 缓存输入 tokens × 缓存输入单价
              + 计费输出 tokens × 输出单价) / 1,000,000

方案成本 = 所有 Boss 调用成本 + 所有 Worker 调用成本
节省比例 = (单 Boss 基线成本 - boss 方案成本) / 单 Boss 基线成本
```

公式适用于具有这些计价分类的模型；其他模态或特殊计费类别按对应官方规则扩展。若输入总量包含缓存量，先减去缓存量，避免重复计费。推理 tokens 按该模型官方计费归属处理，已包含在计费输出中的部分不得重复加总。计入启动上下文、调度、验收、失败尝试和纠偏的全部模型调用；等待本身不虚构 token 消耗，轮询产生的模型调用应计入。工具或服务的非 token 费用单独列出。

Worker 自动选择以官方价格为成本依据，同时考虑预计输入、输出、缓存和返工量，不能仅按最低输入单价选模型。没有官方价格的模型标记 `price unknown`，不编造单价或宣称最便宜；显式指定的模型仍保留硬约束，缺少价格不构成换模型理由。

委派的简短成本判断为：预计省下的 Boss 执行成本，应超过 Worker 执行成本与新增的 Boss 调度、验收、返工成本。单一输入单价之比不能当作整项任务节省比例。正式对照测试用于校准默认粒度；日常运行不重复执行单 Boss 基线，也不为每个叶子任务重新查价或生成长篇成本分析。

用匹配任务比较“Boss 单独执行”和“Boss + Worker”：同一验收标准、相同初始文件、尽量一致的模型设置；记录质量、各模型分类 token 用量、官方价格折算成本、完成时间与纠偏次数。基线成本为零时节省比例不适用。没有实际运行基线时可给出明确标注的估算，不能作为实测节省比例。

报告区分“实测用量 × 官方价格”和“估算用量 × 官方价格”。无法取得完整 tokens 或价格时，标明缺失范围，必要时给出有依据的区间；无法估算则记 `unknown`，不能将缺失值当成零。账号级额度变化可能混入其他会话消耗，仅供辅助参考。token 软目标与轮数限制不是硬计费上限。

## 12. 验收清单

| 场景 | 必须观察到的行为 |
| --- | --- |
| Boss 为 B，指定 Worker A | Boss 保持当前会话；实际调用配置明确为 A |
| 开头指定 A，后续不再提 boss 或模型 | 同一 session 的后续委派继续使用 A |
| 用户切换到 B | 新任务和跟进使用 B；不再向 A 实例追加工作 |
| 切换时 A 仍在运行 | 明示旧任务继续完成；要求立即切换时停止并核对部分结果 |
| 切换目标 B 不可用 | 暂停新的委派，不静默沿用 A |
| 压缩或恢复同一 session | 恢复模型锁定并重新校验；状态缺失时明确报告 |
| 另开 session 或多 session 并行 | 各自保存选择，互不覆盖，不修改全局默认 |
| A 不可用或被角色配置覆盖 | 不启动替代模型；解释具体冲突 |
| 当前 Boss ID 不可读 | 报 unknown/current-session，不猜名称 |
| 原对话很长 | Worker 仅收到任务包及平台必要上下文，不全历史 fork |
| 需求含糊 | Boss 先消歧或委派有限事实定位，不把整体理解交给 Worker |
| 简单任务 | 合理选择 direct，不为流程而增加子代理 |
| 两任务修改同一资源 | 串行或真实隔离，无互相覆盖 |
| Worker 声称成功但证据不足 | Boss 补核，不能直接宣布完成 |
| Worker 连续失败 | 有限纠偏；指定模型不被静默替换 |
| 用户中途取消或改变需求 | 停止/更新相关任务，不整合失效结果 |
| 不支持动态模型的平台 | 使用已核实配置或适配器；否则说明能力缺口 |
| 缺少用量数据 | 不编造成本和节省比例 |

发布门槛：模型约束、上下文控制和结果真实性场景全部通过；质量满足同一验收标准。建议将代表性任务的完成时间中位数不超过单 Boss 基线 1.2 倍作为“均衡节省”的初始实验目标，并争取总可比较消耗下降。这是待实测的目标，不是已经达到的效果或对所有任务的保证。

## 13. 默认策略与已知限制

- 成本/速度偏好：默认均衡节省，可由用户调整；尚无实测节省比例。
- 触发方式：默认遵循所在平台正常 skill 发现机制，同时支持显式调用；若希望仅显式调用，再配置平台可用的限制。
- 非原生桥接：第一版不自动启用外部 API、安装扩展或修改全局配置；将来出现具体能力缺口时，再确定适配方式和授权范围。

同一 session 的选择应持续保留；但纯指令不能保证每个宿主在压缩或重启后自动加载状态。缺少恢复机制时必须报告限制，不能假定已经实现持久化保障。
